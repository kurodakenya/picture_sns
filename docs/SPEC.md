# 写真SNS（仮称）仕様書

最終更新：2026-11-13

## 1. プロジェクト概要

### 1.1 コンセプト

承認制の小規模写真投稿SNS。ログインした人だけが閲覧・投稿でき、利用者はオーナー（管理者）が承認した人のみに限定される。

### 1.2 目的

- AWSサーバーレスの実践経験を積む（転職ポートフォリオの柱）
- 運用費ほぼ無料で長期間公開しておける構成にする
- GitHub公開して個人開発の実績にする

### 1.3 公開方法

- 独自ドメインは取得しない
- CloudFrontのサブドメイン（`https://◯◯.cloudfront.net`）で公開
- HTTPS・証明書は無料（CloudFront標準）

## 2. ユーザーと権限

### 2.1 ユーザー種別

| 種別 | 説明 |
|---|---|
| オーナー（管理者） | AWSコンソールでユーザー承認・却下を行う。アプリ内の管理画面は設けない |
| 承認済みユーザー | ログイン・閲覧・投稿・いいね・自分の投稿削除が可能 |
| 未承認ユーザー | 登録申請済みだがオーナー未確認。ログイン不可 |
| 未登録者 | アプリにアクセスできるがログイン画面のみ表示 |

### 2.2 承認フロー

1. 利用希望者がメールアドレス＋パスワード＋表示名で登録申請
2. Cognitoにアカウントが「未確認」状態で作成される → ログイン不可
3. オーナーがAWSコンソール上で申請を確認し、承認操作を実施
4. 「確認済み」になりログイン可能
5. 却下する場合は未確認ユーザーを削除

### 2.3 表示名

- 登録申請時に「表示名」を入力（メールアドレス、パスワードと合わせて3項目）
- Cognitoの `preferred_username` 属性に保存
- バリデーション：1〜20文字、空白のみ不可
- 登録後の変更不可（Postsテーブルに非正規化して保存するため）
- 投稿時にPostsテーブルへ `userName` として保存
- フィード取得時はPostsテーブルの `userName` をそのまま返す（Cognito問い合わせ不要）

## 3. 画面仕様

### 3.1 画面一覧

| # | 画面名 | 概要 | 認証 |
|---|---|---|---|
| 1 | ログイン / 登録申請 | メール＋パスワードでのログインおよび新規登録申請 | 不要 |
| 2 | タイムライン | 全ユーザーの投稿を新しい順に一覧表示 | 必要 |
| 3 | 投稿画面 | 写真1枚＋キャプションを投稿 | 必要 |
| 4 | マイ投稿一覧 | 自分の投稿を一覧表示。ここから削除操作を行う | 必要 |

### 3.2 画面詳細

#### 3.2.1 ログイン / 登録申請画面

- ログインフォーム（メールアドレス、パスワード）
- 新規登録フォーム（メールアドレス、パスワード、表示名）
- 登録申請後は「承認待ち」のメッセージを表示
- 未承認ユーザーがログインを試みた場合はエラーメッセージ表示

#### 3.2.2 共通ヘッダー

ログイン画面以外の全画面で表示。

- アプリ名
- ナビゲーション（タイムライン / 投稿 / マイ投稿）
- ログアウトボタン

#### 3.2.3 タイムライン画面

- ログイン済みユーザーの投稿を新しい順に表示
- 各投稿の表示内容：画像、キャプション、投稿者名、投稿日時、いいね数
- 画像タップで原寸画像を表示
- いいねボタン（トグル：いいね / いいね取り消し）
- 20件ずつ追加読み込み（無限スクロールまたは「もっと見る」ボタン）
- 投稿画面への遷移ボタン

#### 3.2.4 投稿画面

- 写真選択（1枚のみ）
- キャプション入力欄（上限：200文字）
- 対応形式：JPEG / PNG / HEIC（HEICはクライアント側でJPEGに変換）
- ファイルサイズ上限：10MB
- クライアント側でEXIF（GPS等）を除去してからアップロード
- 投稿ボタン押下で署名付きURLを取得 → S3へ直接アップロード → メタデータをAPI登録
- 投稿完了後はタイムラインに遷移

#### 3.2.5 マイ投稿一覧画面

- 自分の投稿のみをタイムラインと同じ形式で一覧表示
- 各投稿に削除ボタンを配置
- 削除は確認ダイアログ表示後に実行
- 削除時はS3の画像も一緒に削除

## 4. 機能仕様

### 4.1 投稿機能

| 項目 | 仕様 |
|---|---|
| 写真枚数 | 1投稿につき1枚 |
| キャプション | 任意入力、上限200文字 |
| 対応画像形式 | JPEG / PNG / HEIC（HEICはクライアント側でJPEGに変換） |
| ファイルサイズ上限 | 10MB（確定） |
| 画像の保存期間 | 無期限（ユーザーが手動で削除しない限り保持） |
| アップロード方式 | 署名付きURLによるS3直接アップロード |
| EXIF除去 | クライアント側でアップロード前に除去（GPS等のプライバシー情報を削除） |

### 4.2 タイムライン機能

| 項目 | 仕様 |
|---|---|
| 表示対象 | ログイン済み全ユーザーの投稿 |
| 並び順 | 新しい順（createdAt降順） |
| ページネーション | カーソルベース、20件ずつ追加読み込み |
| 画像表示 | 原寸画像を配信（CSSでサイズ制御）、タップで原寸表示 |
| 画像URL | 署名付きURL（有効期限つき） |

### 4.3 いいね機能

| 項目 | 仕様 |
|---|---|
| 制限 | 1投稿につき1ユーザー1回 |
| 取り消し | 可能 |
| 重複防止 | Likesテーブルの postId × userId で制御 |

### 4.4 削除機能

| 項目 | 仕様 |
|---|---|
| 対象 | 自分の投稿のみ |
| 削除範囲 | DynamoDBレコード＋S3の画像 |
| 確認 | 削除前に確認ダイアログを表示 |

### 4.5 閲覧範囲

- ログイン済みユーザーのみ全投稿を閲覧可能
- フォロー概念なし（全投稿が全ログインユーザーに見える）
- 未ログイン状態ではコンテンツにアクセスできない

## 5. API仕様

### 5.1 エンドポイント一覧

すべてのエンドポイントはCognito JWTオーソライザーによる認証が必要。

| メソッド | パス | 概要 |
|---|---|---|
| POST | `/uploads/presign` | アップロード用署名付きURLの発行 |
| POST | `/posts` | 投稿の登録（S3キー＋キャプション） |
| GET | `/feed` | タイムライン取得（カーソル付きページネーション） |
| GET | `/me/posts` | 自分の投稿一覧取得 |
| DELETE | `/posts/{postId}` | 投稿削除（メタデータ＋S3画像） |
| PUT | `/posts/{postId}/like` | いいね |
| DELETE | `/posts/{postId}/like` | いいね取り消し |

### 5.2 共通エラーレスポンス

すべてのAPIエンドポイントは以下の形式でエラーを返す。

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Caption must be 200 characters or less"
  }
}
```

| HTTPステータス | エラーコード | 発生場面 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | リクエスト不正（必須項目欠落、形式不正、キャプション超過等） |
| 400 | `INVALID_FILE_TYPE` | 対応外の画像形式 |
| 400 | `FILE_TOO_LARGE` | ファイルサイズ上限超過 |
| 401 | `UNAUTHORIZED` | JWT無効・期限切れ（API Gatewayが自動返却） |
| 403 | `FORBIDDEN` | 他ユーザーの投稿を削除しようとした等 |
| 404 | `NOT_FOUND` | 指定した投稿が存在しない |
| 500 | `INTERNAL_ERROR` | サーバー内部エラー |

- `code`: フロント側での分岐に使う機械可読な文字列
- `message`: 開発・デバッグ用の人間可読な説明（ユーザー向け表示文言はフロント側で定義）
- 401はAPI GatewayのJWTオーソライザーが自動で返すため、Lambda側では基本的に発生しない

### 5.3 エンドポイント詳細

#### POST /uploads/presign

署名付きURLを発行し、クライアントからS3への直接アップロードを可能にする。

**リクエスト**
```json
{
  "contentType": "image/jpeg",
  "fileName": "photo.jpg"
}
```

**レスポンス**
```json
{
  "uploadUrl": "https://s3.ap-northeast-1.amazonaws.com/...",
  "s3Key": "uploads/{userId}/{uuid}.jpg"
}
```

#### POST /posts

S3にアップロード済みの画像のメタデータをDynamoDBに登録する。

**リクエスト**
```json
{
  "s3Key": "uploads/{userId}/{uuid}.jpg",
  "caption": "今日の一枚"
}
```

**レスポンス**
```json
{
  "postId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "createdAt": "2026-11-13T12:00:00.000Z"
}
```

#### GET /feed

タイムラインを取得する。カーソルベースのページネーション。

**クエリパラメータ**
| パラメータ | 必須 | 説明 |
|---|---|---|
| cursor | No | 次ページ取得用カーソル（前回レスポンスのnextCursor） |
| limit | No | 取得件数（デフォルト: 20、最大: 50） |

**レスポンス**
```json
{
  "posts": [
    {
      "postId": "xxx",
      "userId": "xxx",
      "userName": "表示名",
      "caption": "今日の一枚",
      "imageUrl": "https://...(署名付きURL)",
      "createdAt": "2026-11-13T12:00:00.000Z",
      "likeCount": 5,
      "likedByMe": true
    }
  ],
  "nextCursor": "xxx"
}
```

#### GET /me/posts

自分の投稿一覧を取得する。レスポンス形式はfeedと同様。

#### DELETE /posts/{postId}

自分の投稿を削除する。DynamoDBレコードとS3画像を削除。
他ユーザーの投稿を削除しようとした場合は403エラー。

**レスポンス**
```json
{
  "deleted": true
}
```

#### PUT /posts/{postId}/like

投稿にいいねする。既にいいね済みの場合は冪等（200を返す）。

#### DELETE /posts/{postId}/like

いいねを取り消す。未いいねの場合は冪等（200を返す）。

## 6. 非機能要件

### 6.1 パフォーマンス

- タイムライン表示は署名付きURLで画像配信（MVPではサムネイルなし、CSSでサイズ制御）
- 画像アップロードはS3直接アップロードでLambdaの負荷を回避
- API Gatewayのデフォルトタイムアウト（29秒）で十分な想定

### 6.2 コスト

- 月額0〜数十円以内に収める
- 常時起動のサーバー・DBを持たない
- NAT Gatewayは使用しない（月約$45の固定費回避）
- CloudWatch Logsの保持期間を短めに設定

### 6.3 セキュリティ・プライバシー

- S3バケットは完全非公開、署名付きURL（有効期限つき）のみでアクセス
- クライアント側でEXIF情報（GPS等）を除去してからアップロード
- アップロード制限：画像形式のみ、サイズ上限設定
- 承認制により利用者をオーナーが把握できる範囲に限定
- Cognito JWTオーソライザーによるAPI認証

### 6.4 可用性

- AWSマネージドサービスのSLA準拠
- 個人利用規模のためマルチリージョン等は不要
